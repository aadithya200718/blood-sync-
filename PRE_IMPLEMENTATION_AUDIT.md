## 5. Identified Architectural Gaps & Required Additive Adjustments

1. **Role Model**: `users.role` enum is currently `'Admin','Technician','Manager','Auditor'`. Must add `'Patient'` via additive `ALTER TABLE users MODIFY COLUMN role ENUM('Admin','Technician','Manager','Auditor','Patient')`.
2. **Patient-to-User Foreign Key**: `patients` table lacks a direct foreign key to `users`. Must add `user_id INT NULL UNIQUE`, with `FOREIGN KEY (user_id) REFERENCES users(user_id) ON DELETE SET NULL`.
3. **Blood Group Verification Status**: `patients` table needs clinical verification status for self-registered patients: `is_verified BOOLEAN DEFAULT FALSE`, `verified_by INT NULL`.
4. **Notifications Architecture**: Existing `alerts` table represents system-wide inventory and equipment warnings, not recipient-targeted or role-targeted technician notifications. We will add a lightweight `notifications` table in `bloodsync` to support real-time technician alerts (REQ ID, unit ID, event type, severity, is_read).
5. **FEFO & Crossmatch Ordering in `match_request()`**: Stored procedure currently prioritizes crossmatched units before FEFO. The selection policy must be corrected to FEFO priority among eligible units, while strictly excluding Incompatible crossmatches.
6. **Re-availability Safety in Expirations**: `expire_reservations_event` in SQL and `schedulerService.ts` in Node must both be hardened so that units with status `ISSUED` can never be reverted to `AVAILABLE` automatically.
7. **Crossmatch Validation in `issue_unit()`**: Stored procedure `issue_unit()` currently allows issuance without verifying whether an active reservation belongs to the specific request and without checking for a recorded Compatible crossmatch. This must be hardened transactionally.
